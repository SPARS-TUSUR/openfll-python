# Архитектурный контракт `SugenoRegressor` и семантика `fit()`

Настоящий документ фиксирует проектную архитектуру scikit-learn адаптера `SugenoRegressor`, формат спецификации нечёткой модели, разграничение гиперпараметров и обученных параметров, а также требования к математическому ядру перед переходом к реализации обучения .

---

## 1. Контекст и архитектурное разделение

В рамках архитектурного проектирования компонентов библиотеки:

1. **`openfll.SugenoEngine`** остаётся неизменным плоским императивным фасадом нечёткой логики и вычислительным ядром. Он не знает о `fit()`, scikit-learn, разбиении на выборки и CV.
2. **`openfll.sklearn.SugenoRegressor`** — отдельный легковесный адаптер, наследующий `BaseEstimator` и `RegressorMixin` из `scikit-learn`.
3. Цепочка исполнения:
   ```text
   Пользователь / scikit-learn Pipeline / GridSearchCV / cross_val_score
                                  ↓
                        SugenoRegressor.fit(X, y)
                                  ↓
     [1] Валидация входных данных (check_X_y)
     [2] Получение матрицы влияния правил (design matrix W)
     [3] Обучение констант заключений (МНК / Ridge)
     [4] Создание и build() нового экземпляра openfll.SugenoEngine
                                  ↓
                        SugenoRegressor.predict(X)
                                  ↓
     [1] Проверка check_is_fitted(self, "engine_")
     [2] Валидация X (check_array)
     [3] Нативный C++ батч-инференс: self.engine_.predict(X)
   ```

## 2. Предлагаемая семантика первой версии (v1)

### 2.1. Объём и ограничения v1
* **Модель**: строго **Sugeno нулевого порядка**, один непрерывный выход (`single-output regression`).
* **Неизменяемая часть**: структура модели (число входов, имена переменных, функции принадлежности входов, логика правил `IF ... THEN`, t-нормы и s-нормы) фиксируется пользователем до обучения и **не изменяется** во время `fit()`.
* **Обучаемая часть**: вектор числовых констант заключений правил $c = [c_1, \dots, c_K]^T$.
* **Алгоритм обучения**: метод наименьших квадратов (МНК, `numpy.linalg.lstsq`) или регуляризованный МНК (Ridge: $(W^T W + \alpha I)^{-1} W^T y$).
* **Что НЕ входит в v1**:
  * Автоматическая генерация структуры правил и функций принадлежности (структурная идентификация);
  * Градиентная или генетическая оптимизация параметров функций принадлежности антецедентов;
  * Многовыходные модели (multi-output);
  * Sugeno первого порядка (линейные следствия вида $c_0 + c_1 x_1 + \dots$).

### 2.2. Математическая предпосылка линейности
Выход модели Sugeno 0-го порядка для сэмпла $x$:
$$y(x) = \frac{\sum_{r=1}^R w_r(x) \cdot c_r}{\sum_{r=1}^R w_r(x)} = \sum_{r=1}^R \bar{w}_r(x) \cdot c_r$$
где $w_r(x)$ — степень выполнения антецедента $r$-го правила, $\bar{w}_r(x)$ — нормализованный вес.

При фиксированных MF антецедентов и нормах величина $\bar{w}_r(x)$ зависит **только от $x$** и не зависит от $c_r$. Следовательно, модель строго линейна по вектору параметров $c$:
$$\hat{y} = \bar{W}(X) \cdot c$$
где $\bar{W}(X) \in \mathbb{R}^{N \times R}$ — матрица нормализованных влияний правил (design matrix).

## 3. Спецификация модели (`model_spec`)

### 3.1. Почему нельзя передавать готовый `SugenoEngine`
1. `SugenoEngine` — stateful объект, обёртывающий C++ указатель, который не поддерживает сериализацию, глубокое копирование `copy.deepcopy()` и требования `sklearn.base.clone()`.
2. В C++ OpenFLL после вызова `build()` конфигурация модели фиксируется навсегда. Повторный `fit()` на новом наборе данных требует построения **нового** экземпляра `SugenoEngine`.

### 3.2. Формат `model_spec`
Конфигурация модели задаётся декларативно как неизменяемая структура данных (словарь либо датакласс `SugenoModelSpec`):

```python
from openfll.sklearn import SugenoModelSpec

spec = SugenoModelSpec(
    inputs={
        "x1": [
            ("low", "triangular", [-10.0, 0.0, 10.0]),
            ("high", "triangular", [0.0, 10.0, 20.0]),
        ],
        "x2": [
            ("low", "gaussian", [0.0, 2.0]),
            ("high", "trapezoidal", [0.0, 5.0, 10.0, 15.0]),
        ],
    },
    rules=[
        'IF x1 IS "low" AND x2 IS "low" THEN y IS "c_low"',
        'IF x1 IS "high" AND x2 IS "high" THEN y IS "c_high"',
    ],
    output_name="y",
    default_t_norm="min",
    default_s_norm="max",
)
```

Также допускается эквивалентный стандартный словарь Python (`dict`), что гарантирует полную совместимость с сериализацией (`pickle`, `joblib`).

## 4. Контракт эстимейтора `SugenoRegressor`

### 4.1. Конструктор (`__init__`)
Конструктор строго следует соглашениям scikit-learn:
```python
class SugenoRegressor(BaseEstimator, RegressorMixin):
    def __init__(
        self,
        model_spec: Mapping[str, Any] | SugenoModelSpec | None = None,
        *,
        default_t_norm: str | None = None,
        default_s_norm: str | None = None,
        solver: str = "lstsq",
        alpha: float = 0.0,
    ) -> None:
        self.model_spec = model_spec
        self.default_t_norm = default_t_norm
        self.default_s_norm = default_s_norm
        self.solver = solver
        self.alpha = alpha
```
**Требования к `__init__`**:
* Все аргументы конструктора имеют значения по умолчанию.
* Аргументы сохраняются в атрибуты с абсолютно идентичными именами (`self.param = param`).
* В конструкторе **запрещены** любые вычисления, создание C++ объектов, валидация данных или преобразования типов (иначе ломается `sklearn.base.clone()`).

### 4.2. Разделение гиперпараметров и обученных атрибутов

| Категория | Имена атрибутов | Назначение |
|:---|:---|:---|
| **Гиперпараметры** (задаются в `__init__`, варьируются в `GridSearchCV`) | `model_spec`<br>`default_t_norm`<br>`default_s_norm`<br>`solver`<br>`alpha` | Определяют топологию нечёткой модели, нормы и параметры регуляризатора МНК |
| **Обученные атрибуты** (появляются **только** после успешного `fit()`, оканчиваются на `_`) | `engine_`<br>`n_features_in_`<br>`feature_names_in_`<br>`coef_`<br>`consequents_`<br>`rule_names_`<br>`rank_` | Содержат скомпилированное C++ ядро с найденными константами, число признаков, список заключений, идентификаторы правил и численный ранг матрицы влияния |

### 4.3. Совместное использование терминов заключений (Parameter Sharing)
Если несколько правил ссылаются на один и тот же терм заключения (например, правило 1 и правило 3 имеют следствие `THEN y IS "medium"`):
* Число независимых обучаемых параметров равно числу **уникальных consequent MF**, а не числу правил.
* Столбцы матрицы влияния для правил с одинаковым следствием суммируются:
  $$W_{*, \text{medium}} = \bar{W}_{*, \text{rule1}} + \bar{W}_{*, \text{rule3}}$$
* Алгоритм находит одно согласованное значение константы `"medium"`, исключая внутренние противоречия модели.

### 4.4. Жизненный цикл `fit(X, y)`
```python
def fit(self, X, y) -> "SugenoRegressor":
    # 1. Валидация гиперпараметров (alpha >= 0, конечное число; solver in ('lstsq', 'ridge'))
    #    - solver='lstsq' требует alpha == 0.0 (чистый МНК через np.linalg.lstsq)
    #    - solver='ridge' требует alpha > 0.0 (L2-регуляризация через np.linalg.solve)
    # 2. Валидация входных массивов (check_X_y, accept_sparse=False, dtype=np.float64)
    # 3. Проверка соответствия размерности X числу входов в model_spec
    # 4. Проверка и валидация consequents (отсутствие дубликатов, соответствие правилам)
    # 5. Извлечение матрицы влияния правил / констант A(X)
    # 6. Решение задачи МНК (lstsq или Ridge)
    # 7. Построение НОВОГО SugenoEngine(), регистрация MF и правил, build()
    # 8. Сохранение обученных атрибутов (self.engine_, self.coef_, self.consequents_,
    #    self.rule_names_, self.rank_, self.n_features_in_)
    return self
```
* Повторный вызов `fit()` полностью пересоздаёт `engine_` и сбрасывает предыдущее состояние.

### 4.5. Сериализация (pickle / joblib)
* `SugenoRegressor` поддерживает сохранение и загрузку через `pickle` / `joblib`.
* В `__getstate__` нативный C++ экземпляр `engine_` исключается из сериализуемого состояния.
* В `__setstate__` скомпилированное C++ ядро автоматически восстанавливается с помощью `_build_engine` на основе `model_spec`, `consequents_` и `coef_`.

### 4.5. Контракт `predict(X)`
```python
def predict(self, X) -> np.ndarray:
    # 1. Проверка состояния обучения
    check_is_fitted(self, attributes=["engine_", "coef_"])
    
    # 2. Валидация признаков
    X = check_array(X, accept_sparse=False, dtype=np.float64)
    if X.shape[1] != self.n_features_in_:
        raise ValueError(...)
        
    # 3. Нативный batch-инференс
    return self.engine_.predict(X)
```
* `predict(X)` использует native batch (`11-12.5 млн сэмплов/сек`).
* Пустые массивы `X` формы `(0, n_features)` корректно возвращают `np.empty((0,), dtype=np.float64)`.
* Входные данные с `NaN` или `inf` отклоняются на этапе `check_array`.

## 5. Требования к backend

Перед реализацией `fit()` в коде необходимо закрыть исследовательский этап:

1. **Проверка математической линейности**: убедиться на реальном C++ `SugenoEngine`, что агрегированный выход при Sugeno 0-го порядка строго подчиняется формуле взвешенного среднего для используемых t-норм.
2. **Получение матрицы влияния правил $W$**:
   * *Вариант без изменения C++*: запуск $K$ базисных батчей через существующий `predict_batch(X)` (положив по очереди $c_k = 1$, остальные $c_{j \neq k} = 0$).
   * *Вариант с расширением C++*: добавление нативного метода `get_rule_activations(X)`, если базисные прогоны окажутся неэффективными на больших датасетах.
3. **Обработка нулевой активации**: если в какой-то точке $x$ ни одно правило не активно ($\sum w_r(x) = 0$), определить контракт OpenFLL (возврат 0.0, fallback или исключение).

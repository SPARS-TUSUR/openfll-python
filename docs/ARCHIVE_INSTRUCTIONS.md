# Как проверить Python API OpenFLL из архива

Эта инструкция относится к локальному архиву с первоначальной MSYS2-сборкой.
Текущая ветка PR сохраняет актуальное имя дистрибутива `openfll_python` и
сценарий выпуска для официального Windows CPython 3.14. Для работы с кодом
через GitHub используйте PR в двух репозиториях; порядок сборки — в `BUILD.md`.

В архиве находится предварительная сборка `openfll 0.3.0.dev1` с сериализацией
и дополнительными методами Python API. Можно просмотреть изменения в коде
либо установить пакет и запустить пример.

## Что находится в архиве

| Файл | Для чего нужен |
|---|---|
| `README.md` | Эта краткая инструкция |
| `ОТЧЕТ.md` | Перечень реализованных возможностей, исправлений, проверок и ограничений |
| `openfll-0.3.0.dev1-…whl` | Готовый установочный пакет для Windows x64 / MSYS2 UCRT64 Python 3.14 |
| `05_serialization_demo.py` | Пример с автоматической проверкой сохранения и загрузки |
| `API.md`, `MAMDANI.md` | Описание методов и пример модели Мамдани |
| `openfll-python.patch` | Изменения в репозитории Python-пакета |
| `python-api-extensions.patch`, `BACKEND_PATCH.md` | Изменения C++-части и пояснение к ним |
| `demo_models/` | Примеры сохранённых JSON-моделей |
| `cpp-tests.log`, `python-tests.log`, `demo.log` | Исходные результаты выполненных проверок |

## Вариант 1. Установить и запустить пример

1. Распакуйте ZIP в отдельную папку.
2. Проверьте окружение: готовый пакет подходит для **MSYS2 UCRT64 Python 3.14**.
   Для обычного Python с python.org этот файл `.whl` не подходит: потребуется
   отдельная сборка расширения из исходников.
3. Если Python и NumPy ещё не установлены в MSYS2, откройте терминал
   **MSYS2 UCRT64** и установите их:

```bash
pacman -S --needed mingw-w64-ucrt-x86_64-python mingw-w64-ucrt-x86_64-python-numpy
```

Затем откройте PowerShell **в папке распакованного архива**. Далее предполагается,
что MSYS2 установлен в `C:/msys64`; при другом расположении измените путь.
Проверьте версию Python: она должна быть 3.14.

```powershell
C:/msys64/ucrt64/bin/python.exe --version
```

Создайте отдельное окружение, установите пакет и запустите пример:

```powershell
C:/msys64/ucrt64/bin/python.exe -m venv --system-site-packages .venv
./.venv/bin/python.exe -m pip install --no-deps ./openfll-0.3.0.dev1-cp314-cp314-mingw_x86_64_ucrt_gnu.whl
./.venv/bin/python.exe ./05_serialization_demo.py --output-dir demo_models
```

Флаг `--system-site-packages` даёт окружению доступ к установленному в MSYS2
NumPy. Флаг `--no-deps` использует эту готовую зависимость.

Пример проверяет три варианта: Сугено с `wtaver`, Сугено с `wtsum` и Мамдани.
Для каждого он сравнивает результаты исходной модели с результатами моделей,
загруженных из строки и файла. Для каждого варианта ожидается сообщение:

```text
Сохранение и восстановление через строку и файл: успешно
```

В конце должно появиться:

```text
Все проверки нативной сериализации успешно пройдены.
```

В папке `demo_models` сохранятся JSON-модели. Повторный запуск перезаписывает
эти демонстрационные файлы. Для запуска примера применять патчи не требуется.

## Вариант 2. Проверить изменения в исходниках

Сначала прочитайте `ОТЧЕТ.md`, `API.md` и `BACKEND_PATCH.md`. Патчи содержат
изменения двух разных репозиториев:

- `python-api-extensions.patch` — для `fuzzy-logic-library`, исходный коммит
  `4b2bfe286d131065092e2a5932b3bc0b777d0b0f` из ветки `python/pybind`;
- `openfll-python.patch` — для `openfll-python`, исходный коммит
  `a9f3b4cb59843e779d034d8876734899b4bc66b7`.

Для применения используйте чистые локальные копии соответствующих исходных
коммитов. Из каталога нужного репозитория сначала проверьте патч:

```powershell
git apply --check "C:/путь/к/распакованному/архиву/имя-патча.patch"
```

Если проверка прошла, примените этот же файл:

```powershell
git apply "C:/путь/к/распакованному/архиву/имя-патча.patch"
```

Команды выполняются отдельно для каждого репозитория с соответствующим патчем.
Подробная инструкция сборки находится в `BUILD.md` Python-репозитория после
применения его патча. На уже изменённые исходники повторно применять патчи
не нужно. Доступ к исходным репозиториям требуется только для работы с кодом;
для установки готового пакета он не требуется.

## Проверки и ограничения

Проверено: 118 C++-тестов и 105 Python-тестов успешно пройдены; один необязательный
тест сравнения с `simpful` пропущен. Сборка документации со строгой проверкой
также прошла. Исходные логи сохранены без перевода, чтобы сохранить точные
сообщения инструментов. Названия методов, команды, идентификаторы в коде и
содержимое технических патчей могут содержать английский текст.

JSON сохраняет структуру модели, но не текущие значения входов. Загруженный
движок уже собран. Имена MF и метаданные графиков нативный формат не сохраняет,
поэтому получение степени принадлежности по прежнему имени MF и построение
графиков на загруженном экземпляре ограничены. Подробности — в `ОТЧЕТ.md`.

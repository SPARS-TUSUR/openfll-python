# Отчёт по воспроизведению нечёткой аппроксимирующей модели трещиностойкости

## 1. Что требовалось сделать

На первом практическом этапе требовалось:

1. изучить исходные экспериментальные данные, скрипт предварительного анализа и статью с описанием методики;
2. использовать экспериментальные записи напрямую, без кластеризации исходных точек;
3. построить нечёткую аппроксимирующую модель, в которой каждая принятая запись участвует в формировании нечёткого правила;
4. рассчитать поверхности отклика `KIC(P, a, c)`;
5. выполнить основной расчёт с помощью OpenFLL;
6. независимо проверить результат с помощью FuzzyLab или Simpful.

## 2. Итог аудита задания

Первый этап выполнен по существу. Построена и запущена нечёткая модель нулевого порядка Такаги–Сугено, рассчитаны три поверхности на сетке, а вычисления OpenFLL независимо сверены с Simpful и реализацией формулы на NumPy.

## 3. Как интерпретированы исходные данные

В исходном файле `full_experimental_data.xlsx` находится 35 наблюдений. В ноутбуке `Исправление.ipynb` представлены несколько вариантов обработки выбросов. Вручную сформированные очищенные наборы содержат `10 + 8 + 8 = 26` наблюдений. Статья также описывает исходную модель с 26 правилами.

Поэтому для основного воспроизведения использованы именно эти 26 записей. Они сохранены в `article_clean_26.csv`; все строки были дополнительно сверены с исходным Excel, численные значения не изменялись.

Здесь остаётся методическая неоднозначность: слова «исходная выборка использовалась полностью» можно понять как использование всех 35 строк Excel, однако структура из 26 правил в статье соответствует очищенной выборке из notebook. Перед окончательным оформлением учебной работы желательно уточнить у преподавателя один вопрос:

> Под полной исходной выборкой имеется в виду исходный Excel из 35 строк или очищенная выборка из 26 строк, использованная для 26 правил в статье?

Если преподаватель подтвердит 35 строк, следует выполнить дополнительный вариант модели с 35 правилами и сопоставить обе поверхности. Это не отменяет уже выполненную реализацию: меняется набор записей и количество правил, а вычислительный конвейер остаётся тем же.

## 4. Реализованная модель

Для входов используются переменные `P`, `a` и `c`, выходом является `KIC`.

- Для `P` заданы 3 гауссовых нечётких множества — по одному на каждое экспериментальное значение `P`.
- Для `a` и `c` задано по 26 гауссовых нечётких множеств — по одному на каждое наблюдение.
- Каждая запись формирует правило вида: `IF P = P_i AND a = a_i AND c = c_i THEN KIC = KIC_i`.
- Для объединения условий используется произведение степеней принадлежности.
- Выход вычисляется как нормированная взвешенная сумма постоянных консеквентов.
- Начальные ширины гауссовых функций определяются детерминированно по расстояниям до соседних центров; также используется нижняя граница ширины, чтобы не возникали участки без активных правил.

Группировка точек в кластеры и сокращение числа правил не выполнялись.

## 5. Полученные результаты

### 5.1. Качество аппроксимации на 26 использованных наблюдениях

| Метрика | Значение |
|---|---:|
| MSE | 0,0034064 |
| RMSE | 0,0583644 |
| MAE | 0,0360092 |
| Максимальная абсолютная ошибка | 0,1777503 |
| `R²` | 0,9443217 |

Значение MSE округляется до `0,0034`. Оно численно согласуется с уровнем ошибки, приведённым в статье, но не является доказательством точного повторения опубликованной оптимизированной модели: статья не содержит всех оптимизированных параметров функций принадлежности.

### 5.2. Проверка с исключением одного правила

Дополнительно каждое наблюдение по очереди исключалось из набора правил, после чего для него выполнялся прогноз:

| Метрика | Значение |
|---|---:|
| MSE | 0,0166569 |
| RMSE | 0,1290615 |
| MAE | 0,1078069 |
| Максимальная абсолютная ошибка | 0,2596130 |
| `R²` | 0,7277406 |

Эта проверка показывает, что модель не только возвращает значения собственных правил, однако она всё ещё использует лишь три экспериментально измеренных уровня `P`. Поэтому она не подтверждает физическую точность для промежуточных концентраций или иных новых режимов.

### 5.3. Поверхности отклика

Для каждого из трёх экспериментальных режимов рассчитана сетка `100 × 100`. Всего получено 30 000 прогнозов без `NaN` и бесконечных значений.

| Концентрация, масс. % | Среднее `KIC` | Стандартное отклонение | Минимум | Максимум |
|---:|---:|---:|---:|---:|
| 0,0 | 0,914956 | 0,248882 | 0,496749 | 1,229360 |
| 0,1 | 0,927264 | 0,240792 | 0,496749 | 1,212524 |
| 0,5 | 1,067359 | 0,126701 | 0,502541 | 1,424505 |

Для построенной поверхности среднее прогнозируемое значение `KIC` увеличивается с ростом концентрации. Это является свойством рассчитанной модели, а не отдельным доказательством физической причинности.

## 6. Независимая валидация

Результат OpenFLL проверен двумя независимыми способами:

1. прямой реализацией формулы взвешенного вывода на NumPy для всех 30 000 точек;
2. моделью Simpful для всех 26 наблюдений и детерминированной выборки из 300 точек поверхностей.

Максимальные абсолютные расхождения:

| Сравнение | Максимальное расхождение |
|---|---:|
| OpenFLL — NumPy, 26 наблюдений | `8,88 × 10⁻¹⁶` |
| OpenFLL — NumPy, 30 000 точек | `2,00 × 10⁻¹⁵` |
| OpenFLL — Simpful, 26 наблюдений | `8,88 × 10⁻¹⁶` |
| OpenFLL — Simpful, 300 точек поверхностей | `6,66 × 10⁻¹⁶` |

Это уровень погрешности вычислений с плавающей точкой. Следовательно, реализация нечёткого вывода в OpenFLL и независимые проверки дают практически одинаковый результат.

Simpful не прогонялся по всем 30 000 точкам, потому что его поэлементный вывод заметно медленнее. Вместо этого использована воспроизводимая выборка из 300 точек по всей области. Полная сетка при необходимости может быть рассчитана, но она не добавит принципиально новой проверки формулы.

## 7. Что получилось и что не получилось

Получилось:

- воспроизвести структуру модели из статьи без кластеризации;
- сформировать 26 правил непосредственно из экспериментальных записей;
- рассчитать и сохранить три поверхности;
- получить конечные значения во всех 30 000 точках;
- подтвердить совпадение OpenFLL, NumPy и Simpful с точностью порядка `10⁻¹⁵`;
- добавить проверку с исключением одного правила;
- добавить автоматические тесты и убедиться, что существующие тесты проекта не сломаны;
- сделать воспроизводимый сценарий запуска и сохранить все таблицы, метрики и изображения.

Не получилось или сознательно не выполнялось:

- невозможно точно восстановить найденные в статье генетическим алгоритмом центры и ширины функций принадлежности, потому что их полный набор не приложен;
- не доказана точность модели на промежуточных концентрациях, так как таких экспериментальных измерений в исходных данных нет;
- полный прогон Simpful по 30 000 точкам заменён репрезентативной проверкой 300 точек из-за производительности;
- вариант с 35 правилами не запускался, поскольку статья и вручную очищенный набор указывают на модель из 26 правил;
- обученный без регуляризации `SugenoRegressor` точно интерполировал обучающие данные (`MSE ≈ 2,55 × 10⁻³⁰`), но получил консеквенты от `−4,61` до `4,99` и поверхность до `3,07`. Это признак переобучения, поэтому такой вариант не принят как основной физически интерпретируемый результат.

## 9. Как самостоятельно повторить запуск

Команды выполняются из корня репозитория в PowerShell. Нативный модуль OpenFLL в проекте собран для MSYS2/UCRT64 Python 3.14.

### 9.1. Один раз подготовить окружение

```powershell
$experimentVenv = Join-Path $env:TEMP 'openfll-py314-fracture-exp'
C:\msys64\ucrt64\bin\python.exe -m venv --system-site-packages $experimentVenv
& "$experimentVenv\bin\python.exe" -m pip install --no-deps -r experiments\fracture_toughness\requirements.txt
```

### 9.2. Запустить вычислительный эксперимент

```powershell
$env:PYTHONPATH = "$(Get-Location)\src;$(Get-Location)"
$env:PATH = "C:\msys64\ucrt64\bin;$env:PATH"
& "$env:TEMP\openfll-py314-fracture-exp\bin\python.exe" `
  -m experiments.fracture_toughness.run_experiment
```

После запуска основные числа находятся в `experiments/fracture_toughness/results/summary.json`, полная поверхность — в `surface_predictions.csv`, а графики — в файлах `surface_openfll_*.png`.

### 9.3. Запустить все тесты

```powershell
$env:PYTHONPATH = "$(Get-Location)\src;$(Get-Location)"
$env:PATH = "C:\msys64\ucrt64\bin;$env:PATH"
& "$env:TEMP\openfll-py314-fracture-exp\bin\python.exe" -m pytest -q
```

Ожидаемый результат текущего состояния проекта: `77 passed`.
